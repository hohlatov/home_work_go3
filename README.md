# Домашние задания по Go — Gateway и Ledger

Два независимых Go-сервиса в одном репозитории, у каждого свой `go.mod`.

```
.
├── gateway/                  # HTTP-шлюз
│   ├── go.mod
│   └── main.go               # HTTP-сервер на :8080, обработчик GET /ping
└── ledger/                   # бизнес-логика
    ├── go.mod
    ├── main.go               # запуск сервиса и демонстрация сценариев
    ├── budgets.json          # бюджеты, загружаемые при запуске
    └── internal/ledger/
        ├── ledger.go         # Transaction, AddTransaction (с проверкой бюджета), ListTransactions
        ├── budget.go         # Budget, SetBudget, LoadBudgets
        ├── ledger_test.go    # тесты транзакций
        └── budget_test.go    # тесты бюджетов и загрузки JSON
```

Нужен Go 1.22 или новее.

## Задание 1. Gateway

```bash
cd gateway
go run .
```

В другом терминале:

```bash
curl -i http://localhost:8080/ping
```

Ожидаемый ответ:

```
HTTP/1.1 200 OK
Content-Type: text/plain; charset=utf-8

pong
```

Другие методы (например, `POST /ping`) получают `405 Method Not Allowed`.
Остановить сервер: `Ctrl+C`.

## Задание 2 (ДЗ 2). Транзакции в Ledger

`ledger/internal/ledger/ledger.go`:

- `Transaction` — структура с полями `ID`, `Amount`, `Category`, `Description`, `Date` (`time.Time`).
- Хранилище — срез `[]Transaction` в памяти, при запуске он пустой. Доступ защищён `sync.RWMutex`.
- `AddTransaction(tx Transaction) error` — назначает `ID = len(slice)+1` и добавляет транзакцию.
  Возвращает ошибку, если сумма равна 0 или категория пустая. Если дата не указана, подставляет текущее время.
- `ListTransactions() []Transaction` — возвращает копию всех транзакций.

## ДЗ 3. Бюджеты и обработка ошибок в Ledger

`ledger/internal/ledger/budget.go`:

- `Budget{Category, Limit}` — бюджет на категорию.
- Хранилище — `map[string]Budget`. Ключ — название категории в нижнем регистре без пробелов по краям,
  поэтому «Еда», «еда» и « ЕДА » считаются одной категорией.
- `SetBudget(b Budget) error` — добавляет бюджет или обновляет лимит. Отклоняет пустую категорию и лимит ≤ 0.
- `AddTransaction` теперь проверяет бюджет. Если для категории задан бюджет, а сумма уже сохранённых
  транзакций вместе с новой больше `Limit`, функция возвращает ошибку `budget exceeded` (`ErrBudgetExceeded`,
  её можно проверить через `errors.Is`) и **не сохраняет** транзакцию. Можно потратить ровно до лимита.
  Суммы сравниваются с точностью до копеек. Проверка и добавление выполняются под одной блокировкой.
- `LoadBudgets(r io.Reader) error` — читает JSON-массив бюджетов и применяет каждый через `SetBudget`.
  Ошибки возвращаются с понятным описанием: пустой ввод, синтаксическая ошибка с позицией, неверный тип поля,
  неизвестное поле (например, опечатка `limt`), не массив, некорректный лимит с номером элемента.
  Если хотя бы один элемент некорректен, ни один бюджет из файла не применяется.

Формат файла `ledger/budgets.json`:

```json
[
  { "category": "Транспорт", "limit": 2000 },
  { "category": "Образование", "limit": 6000 },
  { "category": "Развлечения", "limit": 1500 }
]
```

## Запуск Ledger

Запускать нужно из папки `ledger`, потому что `budgets.json` открывается по относительному пути:

```bash
cd ledger
go run .                              # использует budgets.json
go run . -budgets /path/to/other.json # другой файл бюджетов
```

Что делает `main`:

1. Задаёт начальные бюджеты через `SetBudget`: Еда — 5000, Транспорт — 3000.
2. Загружает `budgets.json` через `os.Open` + `bufio.NewReader` + `LoadBudgets`. Транспорт меняется на 2000,
   добавляются Образование и Развлечения.
3. Показывает ошибки загрузки: отсутствующий файл, битый JSON, неверный тип, опечатку в поле, отрицательный лимит.
4. Прогоняет сценарии добавления транзакций. Для каждого печатается `ПРИНЯТО` или `ОТКАЗ` с причиной,
   а `✓` означает, что результат совпал с ожидаемым.
5. Увеличивает лимит «Транспорт» через `SetBudget` до 2500 и повторяет отклонённую транзакцию, теперь успешно.
6. Выводит сохранённые транзакции и исполнение бюджетов. В конце проверяет, что отклонённых транзакций
   в списке нет.

Фрагмент ожидаемого вывода:

```
=== 4. Добавление транзакций ===
✓ ПРИНЯТО Еда            1250.50  Покупки в супермаркете
✓ ПРИНЯТО Еда            3200.00  Закупка на неделю
✓ ОТКАЗ   Еда             800.00  Ресторан (превышение бюджета)
           причина: budget exceeded: категория "Еда", лимит 5000.00, уже потрачено 4450.50, транзакция 800.00 (доступно 549.50)
✓ ПРИНЯТО еда             549.50  Ровно до лимита
...
=== 7. Исполнение бюджетов ===
Категория         Лимит  Потрачено    Остаток
Еда             5000.00    5000.00       0.00
Образование     6000.00    4990.00    1010.00
Развлечения     1500.00       0.00    1500.00
Транспорт       2500.00    2150.00     350.00

Проверка пройдена: в хранилище 7 транзакций, все отклонённые отсутствуют.
```

## Тесты

```bash
cd ledger
go test -race ./...
```

Тесты покрывают: транзакцию в пределах лимита и ровно до лимита, превышение (транзакция не сохраняется),
регистр в названиях категорий, категорию без бюджета, обновление лимита, валидацию `SetBudget`,
погрешность float64, параллельное добавление, а также `LoadBudgets` на корректных и 10 видах некорректных данных.
